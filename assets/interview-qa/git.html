Git Interview Q&A

125 Git and GitHub interview questions: from basics to advanced workflows, branching strategies, merge conflicts, rebasing, workflows, and production patterns.

Beginner (32)

001What is Git?

Git is a distributed version control system tracking code changes over time, enabling collaboration and accountability.

002What is GitHub?

GitHub is a cloud service hosting Git repositories with collaboration features like pull requests and CI/CD.

003What is a repository?

A repository is a project folder with a .git directory containing the entire history of commits.

004How do you create a repository?

Use git init to create a local repo or git clone url to copy a remote repo.

005What is a commit?

A commit is a snapshot of project state at a point in time with a message, author, and timestamp.

006How do you make your first commit?

Use git add file, then git commit -m "message".

007What is a branch?

A branch is an independent development line. Create with git branch name or git checkout -b name.

008What is the default branch?

The default branch is usually main (formerly master).

009How do you switch branches?

Use git checkout branch-name or git switch branch-name.

010What is a remote?

A remote is a reference to a repository on a server (e.g., origin for the main repo).

011How do you add a remote?

Use git remote add name url.

012What is `git push`?

git push sends commits to a remote repository.

013What is `git pull`?

git pull fetches and merges remote changes (= git fetch + git merge).

014What is `git fetch`?

git fetch downloads remote commits without merging.

015How do you view commit history?

Use git log for detailed history, git log --oneline for summaries.

016What is `git diff`?

git diff shows changes between commits, branches, or working directory.

017How do you undo changes?

Use git checkout -- file to discard changes, or git reset HEAD to unstage.

018How do you view the current status?

Use git status to see modified, staged, and untracked files.

019What is `git stash`?

git stash temporarily saves changes to apply later.

020How do you create a tag?

Use git tag v1.0.0 or git tag -a v1.0.0 -m "message" for annotated tags.

021What is `.gitignore`?

.gitignore specifies files Git should ignore (dependencies, secrets, build artifacts).

022How do you configure Git?

Use git config --global user.name "Name" and git config user.email "email".

023What is SSH for Git?

SSH key pairs authenticate with Git servers without entering passwords.

024How do you generate SSH keys?

Use ssh-keygen -t rsa -b 4096 and add the public key to GitHub.

025What is a pull request?

A pull request proposes merging one branch into another with code review.

026What is a fork?

A fork is a copy of a repository under your account, used for contributing to others' projects.

027How do you contribute to an open-source project?

Fork, create a branch, make changes, push, open a pull request.

028What is a commit message best practice?

Write in imperative mood ("Add feature", not "Added feature"), keep first line under 50 characters.

029How do you view a specific commit?

Use git show commit-hash to see details.

030What is `git blame`?

git blame shows who changed each line and in which commit.

031What is a hook?

Git hooks run scripts on certain events (pre-commit, pre-push, etc.).

032How do you undo the last commit?

Use git reset --soft HEAD~1 to undo but keep changes, or --hard to discard changes.

Intermediate (36)

033What is a merge conflict?

A merge conflict occurs when two branches change the same part of a file. Manually resolve by choosing which version to keep.

034How do you resolve merge conflicts?

Edit conflicted files to choose versions, then git add and git commit.

035What is a merge?

A merge combines two branches, creating a commit that includes both histories.

036What is rebase?

Rebase replays commits from one branch onto another, creating a linear history.

037When do you use merge vs. rebase?

Use merge for shared branches (preserves history). Use rebase for local branches before pushing (cleaner history).

038What is an interactive rebase?

git rebase -i allows editing, squashing, or reordering commits.

039How do you squash commits?

Use interactive rebase, mark commits as squash to combine with previous commit.

040What is cherry-pick?

git cherry-pick commit-hash applies a specific commit to the current branch.

041What is a revert?

git revert commit-hash creates a new commit undoing the specified commit (safer than reset).

042What is the difference between `reset` and `revert`?

reset rewrites history (don't use on public branches). revert creates a new commit (safe for shared branches).

043What is a branching strategy?

Branching strategies organize team workflows (Git Flow, GitHub Flow, trunk-based development).

044What is Git Flow?

Git Flow has main, develop, feature, release, and hotfix branches.

045What is GitHub Flow?

GitHub Flow is simpler: main + feature branches, merge via pull request, deploy from main.

046What is trunk-based development?

All developers commit to main (trunk) with short-lived feature branches, emphasizing continuous integration.

047How do you handle conflicts in pull requests?

Resolve locally on the feature branch, then push. GitHub auto-updates the PR.

048What is a code review?

Code review is examining changes before merge, catching bugs and enforcing standards.

049How do you request changes in a pull request?

Leave comments requesting specific changes, request re-review after fixes.

050What is `git reflog`?

git reflog shows recent HEAD changes, useful for recovering lost commits.

051How do you undo a pushed commit?

Use git revert on shared branches or git reset --force on personal branches (carefully).

052What is a remote tracking branch?

Remote tracking branches like origin/main reflect the state of remote branches locally.

053How do you delete a branch?

Use git branch -d branch-name locally, git push origin --delete branch-name remotely.

054What is `git bisect`?

git bisect binary-searches commits to find which one introduced a bug.

055What is `git grep`?

git grep searches project history for strings/patterns.

056What is `.gitattributes`?

.gitattributes specifies line endings (CRLF vs LF), merge strategies per file type.

057What is submodule?

Submodules embed another Git repository inside your project.

058How do you use submodules?

Use git submodule add url path to add, git clone --recurse-submodules to clone with submodules.

059What is sparse checkout?

Sparse checkout allows cloning only parts of a repository.

060What is shallow clone?

git clone --depth=1 clones only recent history, faster for large repos.

061What is a worktree?

git worktree creates multiple working directories from one repository.

062How do you handle large files?

Use Git LFS (Large File Storage) for files > 100 MB.

063What is a pre-commit hook?

Pre-commit hooks run before commits, enforcing checks (linting, testing, formatting).

064What is a pre-push hook?

Pre-push hooks run before pushing, catching issues before leaving local machine.

065How do you configure team workflows?

Set branch protection rules, require pull request reviews, require CI checks before merge.

066What is CODEOWNERS?

CODEOWNERS specifies who must review changes to specific files.

067What is semantic versioning?

Semantic versioning uses MAJOR.MINOR.PATCH format (e.g., 1.2.3).

068How do you release versions?

Tag commits with version numbers, document changes in release notes.

Advanced (15)

069How do you optimize Git repository performance?

Use git gc to compress objects, shallow clones for large histories, shallow submodules.

070How do you migrate from one Git provider to another?

Use git push --mirror to copy all branches, tags, and commits.

071How do you implement secure Git workflows?

Use SSH keys, enforce branch protection, require code review, enable audit logging.

072How do you manage Git at enterprise scale?

Use multiple repositories by team, implement consistent workflows, automate CI/CD.

073How do you handle Git security vulnerabilities?

Scan for exposed secrets, rotate keys, enable two-factor authentication.

074How do you implement Git disaster recovery?

Maintain backups, use multiple remotes, test recovery procedures.

075How do you optimize `.gitignore`?

Keep it efficient, use patterns, avoid ignoring version-controlled files.

076How do you implement custom Git workflows?

Write Git hooks, enforce rules with pre-commit, automate with CI/CD.

077How do you handle Git LFS at scale?

Use LFS bandwidth allowances, implement retention policies, monitor storage.

078How do you migrate to monorepo?

Use tools like Lerna or Yarn workspaces, maintain history with git subtree.

079How do you implement monorepo workflows?

Use conditional CI/CD, CODEOWNERS for ownership, shared libraries, coordinated releases.

080How do you handle Git performance with large files?

Use shallow clones, partial clones, Git LFS, object pooling.

081How do you automate Git workflows?

Use GitHub Actions, GitLab CI, or Jenkins to run tests, builds, deployments.

082How do you implement GitOps?

Git is source of truth, automated deployments triggered by Git changes.

083How do you handle Git secrets?

Scan with tools like git-secrets or TruffleHog, rotate exposed credentials.
